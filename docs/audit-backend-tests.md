> Scope read in full: `src/InterviewAssistant.Backend/**` (38 files, 7,156 lines incl. migrations; 27 files / 3,082 lines excl. migrations), `src/InterviewAssistant.Client/**` (10 files, 973 lines), `src/InterviewAssistant.Contracts/ApiContracts.cs` (92 lines — required for request/response shapes), plus structured inventory of `tests/**` (73 `.cs` files, 13,343 lines; 155 files total incl. fixtures), root docs, `docs/**`, `knowledge/**`, `samples/**`.

Backend hosts on port **8080** (Docker/Railway; also listens on `$PORT` if different). This backend is **shared, unchanged, by Android** — Android is a new client of the same `/api/v1`.

## 8. Sessions, metering & usage — exact rules

**Start (`StartAsync`, all under per-user Postgres advisory xact lock):**
1. Maintenance → 503. IdempotencyKey required, ≤80 chars. `Relay` must be true — old direct-secret clients get 426.
2. Device must be active (`RequireActiveAsync`).
3. Idempotency: same (user, key) with an active lease returns that lease; ended lease → 409 `session_ended`; `SecretsIssued > MaxSecretsPerSession` (see below) → 429 `secret_rate`.
4. New lease only — last-hour counts: abandoned (ended `heartbeat_timeout`) ≥ **8** or total starts ≥ **240** → 429 `session_start_rate`. (Client-initiated pause/resume creates normally-stopped leases and does not hit the abandoned cap.)
5. Allowance: `LiveRemaining` Effective ≤0 splits into: Period ≤0 → 402 `allowance_exhausted`; Today ≤0 → 429 `daily_live_cap` ("resets at 00:00 UTC"); otherwise (global) → 503 `global_cap`.
6. Same-device active leases are ended first (billed tail, reason `replaced_on_device`, status stopped). Active leases on *other* devices ≥ `MaxConcurrentSessions` (1 on both plans) → 409 `concurrent_limit`.
7. New `InterviewSession` (Started = LastHeartbeat = now, `AllowanceAtHeartbeatSeconds = remaining`). Response: `MaxDurationSeconds = min(MaxSessionMinutes*60 = 7200, remaining)`; credential = relay credential expiring at `Started + MaxDuration`; heartbeat interval 30 s; remaining split Period/Today reported separately.

**Heartbeat (`HeartbeatAsync`, same lock):** unknown → 404; non-active → 200 inactive response; `Sequence ≤ stored` → 409 `replayed_heartbeat`. Elapsed = clamp(now − LastHeartbeat, 0, **90 s**) — the timeout bound is the anti-under-reporting rule: stretched heartbeats can never bill less than real elapsed, and never more than 90 s per beat. Billable = min(elapsed, remaining-before); records `live_seconds`, adds to `MeteredSeconds`, updates LastHeartbeat/Sequence/`AllowanceAtHeartbeatSeconds`. Ends lease when remaining ≤0 → status `exhausted`, reason `allowance_exhausted` (period) / `daily_cap` (today) / `global_cap`; or when session age ≥120 min → status `stopped`, reason `max_duration`.

**Every lease end bills the tail** (`BillTailAsync`): tail = clamp(now − LastHeartbeat, 0, 90 s), billable = min(tail, remaining). Used by Stop (`client_stop`), device revocation (`device_revoked`), admin disable / EndAll (caller reason, e.g. `account_disabled`), same-device replacement, and sweeper expiry. **Pause bills nothing extra** because the client ends the lease on pause (resume = new lease).

**Expiry (`ExpireStaleAsync`, sweeper every 30 s):** candidates = active with LastHeartbeat < now−90 s; re-checked inside the user lock (a just-arrived heartbeat wins); billed tail, status `expired`, reason `heartbeat_timeout`.

**Relay window (`RelayMayRun`):** active AND `(now − LastHeartbeat) < min(AllowanceAtHeartbeatSeconds, 90) − 5 s` (`RelayCheckMarginSeconds = 5`, > 2× the max 2 s relay check interval). Relays re-check every ≤2 s in DB (`RelayLeaseActiveAsync` also requires `RelayConnectionId` == this connection — a newer connection on any replica wins). `OpenRelayAsync`: lease must satisfy RelayMayRun, device active, allowance >0, `SecretsIssued ≤ MaxSecretsPerSession` where **`MaxSecretsPerSession = MaxSessionMinutes + 5 = 125`**, then increments SecretsIssued and stamps RelayConnectionId — credential minting happens *outside* the lock.

**Answers accounting:** every `/answers/stream` records 1× `answer_request` (with SessionId when live). Live answers require an active lease. Manual answers additionally record 1× `manual_answer`, bill **zero** live seconds, cap **300/day**. Prep answers require an owned prep job, increment `PreparationJob.AiRequests`, cap **80/job**. Prep jobs themselves: 1× `prep_job` usage per job, quota = plan `PrepJobsPerMonth` per **calendar month** (Trial 2, Pro 20).

## 9. Billing / Paddle flow — exact

**Checkout:** client `POST /billing/checkout {planCode}` → server validates purchasable plan + no existing sub in {active, trialing, past_due, paused} → `PaddleBillingProvider.CreateCheckoutUrlAsync`: `POST {ApiBaseUrl}/transactions` Bearer ApiKey, body `{items:[{price_id: first non-empty catalog price id, quantity:1}], custom_data:{user_id}, collection_mode:"automatic", customer_id? (if known)}` → returns `data.checkout.url` (the Paddle default payment link, which points at this server's `/pay`); missing URL → 502 with operator log hint. `/pay?_ptxn=…` loads Paddle.js with the public ClientToken and Paddle completes payment. No key → 503 `billing_not_configured`; Paddle unreachable → 503 `billing_unavailable`; API failure → 502 `checkout_failed`.
**Portal:** `POST /customers/{customerId}/portal-sessions` with `{subscription_ids:[…]?}` → `data.urls.general.overview`.
**Prices:** `GET /prices/{id}` → `FormatPrice` (§1.4), cached 1 h; any failure → null display (never invented).
**Webhook (`POST /webhooks/paddle`):** raw body read with buffering (signature is over the *exact* bytes); >1 MB → 413. `PaddleSignature.Verify`: header `ts=…;h1=…` (multiple h1 allowed), `h1 = hex(HMAC-SHA256(secret, ts + ":" + rawBody))`, constant-time compare, |now − ts| ≤ **300 s**. Bad signature → 401 (processor never runs). Processor: parse JSON (invalid → 400), require `event_id` (≤100) and `occurred_at` (missing → 400, it drives ordering). Duplicate event_id (pre-check or unique-violation on save) → `duplicate`, processed once. Event row + state change commit in **one transaction**; real failure → exception → Paddle retries, nothing half-committed.
**Event handling:**
- `subscription.*` → `ApplySubscriptionAsync`: resolve sub by provider sub id → by `custom_data.user_id` (must be a known non-deleted user; creates row) → by customer id; else ignored. Ordering: event older than `LastEventOccurredUtc` for the same sub → ignored. An event for a *different* sub id: non-{active,trialing} events are ignored while the current sub grants paid access; older ones ignored regardless. Plan resolved from `items[0].price.id`/`price_id` via catalog `ByPaddlePrice`; unmapped price (when a price id is present) → throws 503 `price_not_mapped` **without recording the event** so Paddle's retry applies it after the mapping is fixed. Applies: status (truncated 16), period start/end from `current_billing_period`, `CancelAtPeriodEnd = (scheduled_change.action == "cancel")`, entering past_due sets `GraceUntilUtc = occurred + PastDueGraceDays (7)`, active/trialing clears grace, stamps LastEventOccurredUtc, then `RecomputeRevocationAsync`.
- `transaction.completed` → `LinkCustomerAsync`: upserts `BillingTransaction` (Paid rule §3; billed_at fallback occurred; billing_period start/end), links customer/subscription to the known user when `custom_data.user_id` matches (otherwise payment is still recorded for later refund handling; `ProviderSubscriptionId` only filled if empty — subscription events decide the current sub), recomputes revocation.
- `adjustment.created|updated` → `ApplyAdjustmentAsync`: requires id (≤100) + transaction_id; per-adjustment ordering (older than stored `OccurredUtc` → ignored); upserts row (sub id falls back to the transaction's sub id); resolves sub by sub id then customer id; recomputes revocation; stored even when sub unknown ("applied when the subscription arrives").
- Anything else → ignored ("event type not used").
**Revocation (`RecomputeRevocationAsync`):** `Revokes(a)` = status `approved` AND ((action `refund` AND type `full`) OR action `chargeback`). Access is revoked iff there is ≥1 *covering* payment (Paid, period contains now) and **every** covering payment has a revoking adjustment not undone by a later-or-equal approved `chargeback_reverse` for the same transaction. Revocation stamps the earliest revoking adjustment's time + its action as reason. Partial refunds, credits, chargeback warnings, older-period refunds, zero-value/payment-method-change transactions never revoke. A revoking adjustment whose transaction is not on record → warning log for manual review, access unchanged. Consequences: `PaidAccess` false → plan falls back to trial; `BillingState` = `revoked`; revoked accounts cannot start live sessions on the paid allowance.
**Entitlement timing:** past_due keeps paid access until `GraceUntilUtc`; canceled-at-period-end keeps it until period end; active/trialing whose period ended >3 days ago (RenewalGrace) without a renewal webhook is treated as lapsed.
