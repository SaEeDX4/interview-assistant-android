## 2. Screens, windows, pages & navigation flow

### 2.1 Process / window topology

1. `Program.Main` [STAThread] → **Velopack hooks first** (`VelopackApp.Build().Run()` handles install/update/uninstall and exits) → (`UPDATE_TEST` builds only: `--update-test <feedDir> <result.json>`) → `App.Run()`.
2. `App.OnStartup`: installs 3 global exception handlers (Dispatcher → log + `MainWindow.ShowTransientError(err_unexpected_ui)`, Handled=true — "a live-interview tool must never die"; TaskScheduler → log+observe; AppDomain → log). `--selftest [out.json] [--fixture <dir>]` isolates settings/data to temp, forces cloud API to `https://127.0.0.1:9`. Loads `Branding`, logs start line, prunes logs > 14 days, creates + shows **MainWindow** (the Live Assistant). `ShutdownMode = OnMainWindowClose`.
3. **MainWindow (Live Assistant)** is the main window. **HomeWindow** is a modeless child (`Owner = MainWindow`) opened from it; only one instance (reused/raised). Settings and Pre-interview check are **pages inside HomeWindow**, never separate windows (self-test asserts this).

### 2.7 Navigation flow (complete)

- Routes: `HomeRoute.Parse("page[/section]")`; pages = `start, profiles, interviews, preinterview, reports, account, settings, help`; unknown page → `start`; unknown section dropped by page. Deep links resolve **before** the window shows (target page appears directly).
- Signed-out gate: when cloud-configured + signed out + no workspace, routes `profiles|interviews|reports` are rewritten to `account` (`HomeRoute.Gate`).
- Entry points: Live header Home link / More → Home; Live gear → `settings` (or `settings/<section>`); readiness button/pill → `preinterview`; service banner → `account`; QuickHelp action → `account` (sign-in) or `preinterview`; readiness fixes → `settings/audio`, `account`, `interviews`, `settings/window` (test fixes run in-page); Get-started primary action → per SetupPlanner (sign-in→account, profile→profiles, interview→interviews, prepare→interviews, check→preinterview, start→close Home + start Live).
- Guarded navigation: `NavigationGuard.CanProceedAsync(reason, scope…)` — reasons Navigate/SwitchItem/CloseWindow/SignOut/ReloadData are data-loss; LanguageChange/Resize/ThemeChange/ResourceRefresh/ListRefresh never prompt. ## 9. Error-copy approach (`UiState/ErrorCopy.cs`, 62 lines)

One static mapping, no WPF, unit-tested: **never a raw exception, never "Unknown"**. `Describe(ex, includeReference)`:
- `BackendException` by code first: maintenance (server message), device_revoked/device_unknown, device_limit, plan_required/trial_exhausted/subscription_expired/subscription_paused, allowance_exhausted, daily_live_cap, manual_daily_cap, reauth_required, timeout, session_start_rate, subscription_active, prep_limit, document_limit, account_disabled, update-required → dedicated keys (`svc_*`, `lease_*`, `acct_*`, `err_*`); then by status: 0 → `svc_unreachable`, 401 → `acct_msg_expired`, 403 `svc_forbidden`, 404 `svc_not_found`, 409 `svc_conflict`, 429 `svc_rate_limited`, ≥ 500 `svc_unavailable`, else server message or `err_generic`.
- Reference suffix: `" " + Loc.F("svc_ref", correlationId[..8])` appended when `includeReference: true`; inline section messages pass false (id goes to the log only; `StripReference` removes it).
- `AuthException` → its (already localized) message; Timeout/TaskCanceled → `svc_timeout`; HttpRequestException → `svc_unreachable`; JsonException/NotSupportedException (captive-portal/proxy HTML) → `svc_unreachable`; anything else → `err_generic`. `IsUserCancellation` = OperationCanceledException with the caller's token cancelled → show nothing.
- Same philosophy in logs: `AppLog.Describe` returns **type name only** for IOException/UnauthorizedAccessException/SecurityException (messages contain paths/user names); `AppLog` redacts `sk-…` keys, sanitizes control chars; daily files pruned at 14 days, in-memory ring 400 lines.
